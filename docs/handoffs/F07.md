# F07 — Command gateway handoff

Implemented **2026-11-03** over the integrated F01–F06 interfaces. The common
gateway supports discovery, inspection, construction, registered updates,
relationships, arithmetic, scenes/overlays, evaluation, optional preview,
atomic commit and Undo/Redo. The generic fixture and public construction recipe
load no astronomy modules. F08 agent connectivity is next; no provider, account,
conversation transport, persistence format or new physics was added.

See the [guide](../command-gateway.md), [public recipe](../../examples/command-gateway.mjs)
and [browser harness](../../scripts/verify-gateway-browser.mjs).

## Public contracts

- `src/gateway/commands.js`: `createCommandCatalog({registry,binding,layer})`
  returns `discover`, `has` and `apply(draft,{command,args})`. Apply only stages
  existing public handles. It cannot accept a project. Dynamic commands derive
  parameter/input/asset schemas from the bound registry snapshot. Updates derive
  partial schemas, merge declared slots and preserve pins/dependencies.
- `src/gateway/index.js`: `createCommandGateway({project,registry,binding,layer,
  runtime,commands?,limits?,now?})` returns `dispatch`, `localAuthority`, session/
  turn lifecycle hooks and `setProject`. `commands`, `now`, runtime modules and
  validators are trusted host configuration; request data cannot select them.
- `src/gateway/sdk.js`: local/HTTP/custom-transport clients plus a data-only handle
  author. The client uses F01's JSON-data copier so getters, functions, undefined,
  NaN and custom prototypes cannot be silently normalized differently by HTTP.
  Requests do not execute source. The author retains exact IDs/content/token/key
  for repeat `commit()` calls; edits after submission require a new author.
- `scripts/gateway.mjs`: `discover`, `inspect [id]`, `request FILE|-`, `--url`.
  Prints the same envelope; exit 0 success, 1 gateway rejection, 2 CLI/transport
  failure. Bounded file/stdin reads; no arbitrary script execution command.

Request: `{command,args?,expected?,idempotencyKey?}`. Success:
`{ok:true,command,identity,result,summary?,replayed?}`. Failure:
`{ok:false,command,error,context:{identity}}`. Error fields include `code`,
`category`, `message`, `diagnostics`, `affectedIds`, `paths`, `repairs` and optional
`operationIndex`. Stable underlying validation codes are retained.

`discover.result.commands` contains builtin and installed command declarations,
schemas, defaults, examples, capabilities, limits, diagnostics and authority
requirements. Catalogue parameter schemas come directly from F03; input and
asset slots come from registered contracts. `operationOutputSchema` describes
the staged author result; a dispatched shorthand mutation's `outputSchema`
describes the `{operations,history}` wrapper. F01/F02/F04 semantic validators
remain authoritative beyond structural schema checks. The shared code has no
fixture or domain imports.

`inspect` returns `{graph,history,outputs,requirements,sources}` or
`{node,dependencies}` for an ID. `evaluate` returns the real F04 result in
`result`; `render` returns `{time,results,snapshot}`. Renderer capability data
accepts the existing F05 adapter declaration. Physical time is normalized with
the existing unit system. The runtime retains its single-active-job scheduling:
a newer evaluation/render supersedes older work, including an unfinished render
source loop. Consumers must handle cancellation instead of treating it as data.

`transaction.preview/commit` accept `{operations:[{command,args}]}`. Individual
catalogue mutations are one-operation shorthand. Both validate the staged
candidate with the layer/binding validators even if the host Project has weaker
validators. Final acceptance still belongs to F01. Operations are synchronous;
unknown/nested transaction commands and async author callbacks reject. No
direct graph replacement, module path, registry installation or source-execution
fallback exists.

F01 gained a narrow trusted host hook: `Project.accept(draft,{beforeCommit})`,
`Draft.accept({beforeCommit})`, and `Project.undo/redo(token,{beforeCommit})`.
It receives a deeply frozen detached candidate after ordinary validation, inside
the existing mutation guard, before content/history/revision changes. It must
return undefined or throw synchronously; async/generator callbacks, Promises,
accessors and malformed options reject. F07 uses this hook to validate the actual
candidate (including Undo/Redo targets), then check authority and expected token
last. A validator revoking a turn during final acceptance therefore cannot allow
a commit. History remains validated even for a host Project with weaker validators.
The hook is trusted configuration, never a transported command argument.

Summaries include `created`, `updated`, `removed`, full counts, `truncated`,
`before`, `after` and action. Each ID list is capped at 64. Successful mutations
return operation results and history availability; clients inspect current full
content separately. Cache space is reserved before accepting a write, including
history operations, so an accepted edit is never deliberately left uncached.

## Identity and idempotency

Writes, preview, evaluation and render require the complete
`{projectId,generation,revision}` from inspection. Preview is non-mutating and
reserves neither revision nor IDs. Commit reconstructs and revalidates its
candidate. Competing commits, stale loads and invalid batches preserve accepted
content/history. Undo/Redo restores content while incrementing revision.

Write keys are 1–128 characters. The canonical signature includes command,
arguments, expected identity and the host authority record. Object key order is
irrelevant. Exact retained retries return the original outcome plus
`replayed:true` without another revision, even after later edits or Undo.
Changed payload/context with the same retained key fails `IDEMPOTENCY_CONFLICT`.
The replay identity is historical; it is not a claim that current content still
matches that outcome. Authorization is checked before consulting the cache.

The cache retains successes for **at most 600,000 ms**, **256 entries** and
**8,388,608 bytes**, evicting oldest successes for space. Failures are not stored.
Restart, project switch and load-generation change clear it. These are bounded
in-memory guarantees, not durable exactly-once delivery. After eviction a retry
with its original expected token is stale. To resolve an uncertain old request,
inspect the IDs and current state before deliberately issuing a new token/key.
F09 must explicitly decide persistence, replay and recovery behavior.

## Turn authorization and asynchronous work

`createSession({permissions?})` issues an opaque host object;
`issueTurn(session,{permissions?})` issues a project/load-bound grant whose
permissions can only narrow its session. Permissions are `read`, `write`,
`evaluate`, `render`. `forTurn(turn)` returns only a bound dispatch closure.
Caller labels, cloned objects and JSON actor/session/turn fields cannot mint
grants. Discovery/inspection may be called without a grant; a supplied revoked
grant still rejects rather than silently becoming an anonymous read.

`revokeTurn(turn)` denies later commits/replays and cancels that turn's jobs.
`closeSession(session)` revokes all its turns. `setProject(next)` and detection
of an external Project load invalidate grants/cache and cancel obsolete work.
Local-user adapters read the `localAuthority` getter per call, because it rotates
on load/switch. Runtime work checks authority, project instance, full identity
and computation epoch before/after awaits, between render sources and after
compilation. Late results cannot replace a current snapshot or mutate the graph.
Already accepted effects remain; cancellation is not Undo.

The loopback endpoint is explicitly the local user's authorized connection. It
does not isolate a process that also has native HTTP/filesystem tools. F08 must
expose only the turn closure to scoped tools and manage native capabilities
separately; revoking a gateway turn does not revoke OS permissions.

## Host and browser integration

`scripts/scene-server.mjs` supplies `POST /api/gateway`,
`GET /api/gateway/discovery` and lightweight `GET /api/gateway/state` with
`{identity,history,lastChange}`. The existing F05/F06 `/edit` routes are pure
compatibility translations into gateway transactions/history. They no longer
call Project begin/accept/undo/redo directly. Legacy keyless requests derive a
SHA-256 key from the complete identity and action data; explicit clients use
their own unique keys. Replay compatibility responses contain the original
`gateway` outcome alongside a coherent current graph/token/history.

Both browser modes poll identity once per second, queue external refreshes with
local edits, display change summaries and expose Undo. A stale browser edit may
reconcile once against fresh state using a **new key**, because its expected
context changed. An exact transport retry retains the old key/content. Scene
duplication now keeps the original transform, avoiding a state-dependent legacy
translation that would change on retry. Author an explicit transform update in
the same batch to offset a duplicate.

Polling also compares the last rendered identity, so a cancelled read cannot
leave a newer accepted graph permanently paired with an old scene. Superseded
reads retry with exponential backoff and jitter capped at 16 s; explicit user
actions and successful samples reset it. This prevents two visible tabs from
continually cancelling each other's multi-source renders. The status says
“Waiting for current sample…” while waiting. Retries refresh data only and never
reapply a mutation. The F05 host now starts with clean bootstrap history, matching
the workspace, so initial Undo cannot erase the fixture construction.

Host/Origin checks remain exact loopback checks. Requests require JSON and are
limited to **65,536 bytes**. Static resources remain allowlisted; no credential,
external asset, arbitrary file read/write or code execution route was added.
Default gateway limits are 64 operations, 8 MiB responses/cache, 32 sessions,
128 turns and 128 render sources. Existing graph, scientific, registry, runtime,
scene and workspace budgets remain effective. The HTTP SDK rejects redirects.
HTTP and CLI retain bounded raw bytes until decoding the full UTF-8 request;
Chinese labels survive split network/stdin chunks, and invalid UTF-8 rejects.

Applicability diagnostics are now tagged at the registered guard origin and
preserved through F02 analysis. This avoids classifying a model's declared
`*_LIMIT` guard as an exhausted computation budget. Malformed input, unavailable
capabilities, incompatible connections, applicability, resources, stale state,+cancellation and authorization failures remain distinct. Repairs point to
discovery, inspection, revised preview or new host authority; they never suggest
editing live source to bypass validation.

F08 must:

1. Supply the real provider-independent session transport and one tested adapter.
2. Issue project/session/turn authority in the trusted host; expose only scoped
   dispatch to tools and carry selected component/time context explicitly.
3. Revoke on Stop, completion, error/disconnect and project switch, cancel work,
   and reject late conversational chunks as well as tool writes.
4. Preserve exact request keys across transport retries; reconcile stale state
   explicitly and use a new key for changed content.
5. Surface structured diagnostics, accepted change summaries and Undo without
   introducing mandatory approval for routine authorized reversible edits.
6. Treat native agent filesystem/HTTP capabilities separately from tool grants,
   and retain honest disconnected/offline playback behavior.

F09 owns durable projects/recovery; F10 owns authored timelines/export. F12 will
migrate the existing exoplanet API only after the generic readiness gate.
