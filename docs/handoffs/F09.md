# F09 handoff — portable projects

Implemented and verified on 2026-11-03. Use **Project → Save locally** to keep
a named project across companion restarts. Use **Download JSON** and **Import
JSON…** to move it to another workspace with the required extensions. Reopening
restores the accepted construction, floating windows and physical playhead with
the agent disconnected. [User guide](../portable-projects.md)

## Format and authority

Version 1 uses one UTF-8 JSON document with `format: "cosmic-lego.project"` and
`version: 1`. The accepted F01 graph holds model parameters and inputs,
calculation definitions, scientific Values with units and frames, scene assets
and bindings, and overlay size, position and visibility. The requirement inventory
records transitive F03 extension and implementation pins, including build identity.
The asset inventory carries node and factory IDs, definition hashes, format, source
and license. The data-source inventory can associate datasets with their provenance.
F05 regenerates renderable assets and their content IDs. Worker caches, GPU
objects, Undo history, drafts, selection and provider state stay in memory.

The historical recipe entry and any authored companion files are inert inline
resources. The original construction has its own resource and hash. The separately
labeled generated reconstruction describes the current graph. The UI reports a
match, divergence or absent recipe. Undo can restore a match. Resource names have
no filesystem or network authority. SHA-256 checks detect inconsistent content.
They do not authenticate authorship. [Format implementation](../../src/portable/format.js)

`playback` records `replay-from-initial`, time with units, path selection,
per-node settings and selected ports. F04 initializes from authored inputs and
replays through the saved time, including all random draws. A checkpoint and
its generator state are never needed from the sending process. The workspace
preflights all scene and plot sources plus any additional selected numerical
outputs in a separate runtime. Failures propagate before publication or
replacement. The normal F07 render and evaluation routes use reopened playback
defaults unless the request overrides them. One-off inspection overrides can be
made durable by supplying explicit `playback` to the file API.

Local save and download have independent, opt-in public transcript choices.
An included message carries public ID, turn ID, role and text. The companion
retains up to 256 accepted command summaries with affected IDs, counts and the
historical revision transition. It drops turn/call associations on a
visualization-only export. Opening any project revokes the previous F07/F08
authorities, invalidates in-flight reads and starts a fresh generation with an
empty Undo stack. Opted-in messages reopen as a disconnected archive. A new
native connection requires an explicit Connect action. Review authored source
and public prose before sharing. [Session bridge](../../src/agent-session/index.js)

## Interfaces and recovery

- `createPortableManifest(options)` produces a detached, validated manifest.
  `serializePortableManifest(manifest)` returns formatted JSON.
  `openPortableManifest(input, { registry, binding, layer?, migrations? })`
  returns `{ project, manifest, sourceStatus }`. `portableOptions(manifest)`
  recovers source, replay and sharing metadata for a later snapshot. Low-level
  callers that need a scientific sample invoke F04. The workspace does this
  before completing each file operation. [Format](../../src/portable/format.js)
- `await createPortableStore({ directory, maxBytes?, maxProjects? })` supplies
  `list()`, `read(name, { expectedVersion? })` and
  `save(name, text, { expectedVersion, beforePublish? })`. The default location
  is `.local/projects` and the companion accepts `--project-dir` with an
  absolute, dedicated directory. A disk version is a SHA-256 digest of the
  exact bytes. Pass `null` for create-only or the observed version to replace.
  Names are bounded slot identifiers. [Local store](../../src/portable/store.js)
- Workspace HTTP provides `GET /api/projects/state`, `GET /api/projects/list`
  and `POST /api/projects/{save,open,export,import}`. Each POST requires
  the complete expected active identity. Save also requires the slot name and
  expected disk version. Import accepts an inline parsed `document`. Successful
  responses return `{ ok: true, result }`. The ordinary workspace state includes
  a `portable` entry. The complete request/response contracts appear in the
  [guide](../portable-projects.md) and [host](../../scripts/scene-server.mjs).

A named save stages and syncs a regular file in the same directory. Cooperating
processes acquire a publication lock. The store checks the prior disk version,
calls the host's synchronous revision/transcript guard, checks staging and target
identities, atomically renames the file and syncs its directory. A later accepted
edit stays dirty. A stale save, invalid version, bad resource, missing extension or
failed replay leaves the prior accepted work recoverable. An invalid import also
preserves a live agent turn. Refresh after a stale request. On a disk conflict,
inspect the new version or save to a different name. If directory sync fails
*after* rename, reread the slot before retrying. The lock covers cooperating
writers on a trusted local POSIX filesystem. A PID-reused stale owner or unusual
filesystem may require local inspection. [Workspace coordination](../../src/portable/workspace.js)

six companion and two browser-control tests). Chrome acceptance ran separately.

- The runnable fixture saved at 1 s with seed 2871 and a 0.25 s step, disposed
  the original runtime, and reopened with a fresh registry and worker. The first
  point was `[-3.36, 0.73, -0.74] m` and the accumulator was `3.5`. The seeded
  value was `0.5966447559185326` after four draws. At 2 s the reopened run and
  the uninterrupted run both yielded `1.4712895648553967` after eight draws.
  The checks compare the full generator state and Values, both field arrays,
  eight complete F05 assets, five overlay layouts and all accepted graph data.
  The moved plot and added accumulators correctly diverged from the recorded
  recipe. [Runnable example](../../examples/portable-project.mjs)
- Format checks cover altered pins and assets, source association, hashes, path
  escapes, resource inventory, schema/budget limits, migration, and inert
  executable-looking source. Store checks kill real writer subprocesses immediately
  before and after publication and recover the appropriate complete file. Independent
  stores cannot overwrite each other's newer bytes. [Format tests](../../test/portable-format.test.js)
  · [Store tests](../../test/portable-store.test.js)
- Companion tests save, close the first host and start a fresh one on the same
  directory. They cover settings and field provenance when a producer ID is reused
  or restored by Undo, and asynchronous saves with a caller-owned request. They exercise agent-free playback, stateful replay errors, stale
  saves, equal numeric revisions with different generations, and a late write
  from a revoked test-provider turn. [Host tests](../../test/portable-server.test.js)
- Chrome 156.0.8078.80 passed the five F09 groups. Desktop and 390 px views
  restored the same sample and archived messages. The playhead retained the
  full saved double, including the first sample after reopening. An invalid
  future version returned 400, and a delayed cross-generation edit returned
  409. There were zero unexpected browser errors. F06 workspace (eight groups),
  F07 gateway (four) and F08 mock-agent UI (four) also passed. The native-provider
  evidence belongs to the earlier F08 run. [Browser acceptance](../../scripts/verify-portable-browser.mjs)
  · [F08 handoff](F08.md)

Run the offline suite and example from the repository root. Adding

## Limits and following milestones

Version 1 bounds input to 16 MiB, each accepted graph to 2,000,000 compact JSON
bytes, and selected targets to 256. Replay uses the F04 limits, including 10,000
advancement calls and five seconds per worker job. The workspace also limits
the complete verification to 30 seconds. Large simulations needing durable
checkpoints need a future policy with compatible identities and generator state.
Authoring code may be rerun separately in a trusted environment.

F10 can use the existing saved time and output identities and define a migration
for authored sequences. Its reserved slot currently accepts `null` or inert
`{ version: 0, data: {...} }` up to 16 KiB. Hosts can register trusted,
synchronous, consecutive version transforms through
`createMigrationRegistry().register(fromVersion, toVersion, transform)`.
Migrated documents still undergo current validation. F12 owns conversion of the
legacy exoplanet format and registration of the optional domain implementations.
