# F08 handoff — in-app agent sessions

Implemented and verified locally **2026-11-03**. A learner can select a configured
agent in the floating Conversation window, ask it to construct or revise the
scene, see its public replies and tool outcomes, stop it, and undo accepted
edits. The tested provider is native Codex app-server. No new dependency,
provider subscription, cloud host or credential store was added.

## Run it

Start the workspace with `bash scripts/node.sh scripts/scene-server.mjs --workspace
--port 4326 --codex /absolute/path/to/codex` (one command), then open
[the workspace](http://127.0.0.1:4326/workspace/). Use **Conversation → Codex ·
local app-server → Connect**. The runtime must already support local authentication.
Without `--codex`, the workspace and scientific playback run offline. See the
[setup and protocol guide](../in-app-agent-sessions.md) for the reproducible
configuration, verification commands and primary documentation.

## Delivered interfaces

- [Session bridge](../../src/agent-session/index.js) and [context builder](../../src/agent-session/context.js):
  normalized host session/turn/request IDs, authenticated readiness, public text,
  tool progress/results, permissions/input, completion reasons, bounded snapshots
  and cursor-based events. Exact-content deduplication protects submissions,
  provider events and tool calls. Reused IDs with conflicting content fail.
- [Native adapter](../../src/agent-session/codex.js), [configuration](../../src/agent-session/config.js)
  and [JSONL transport](../../src/agent-session/rpc.js): structured stdio launch,
  real account check, ephemeral thread, dynamic `cosmic_command`, public delta
  and final-message handling, native request replies, interrupt/disconnect.
  Unknown notifications and private reasoning never become transcript items.
- [Local companion](../../scripts/scene-server.mjs): explicit host-owned executable,
  separate authoring directory, bounded `/api/agent/*` endpoints, exact loopback
  Host/Origin checks and accepted-change notifications. Only the trusted host
  constructs adapters and issues F07 turn grants. Browser input cannot choose an
  executable, extra arguments, source module, credentials or grant.
- [Workspace transport](../../src/workspace/session.js) and [conversation UI](../../demo/workspace/app.js):
  agent picker, Connect/Disconnect, honest lifecycle states, per-view drafts,
  streamed transcript, compact tool results, permission/input cards, keyboard
  Send, Stop and retained transcript after disconnect. The original UI injection
  seam remains for explicitly labeled tests and cannot issue gateway authority.
- F07's `discover` command now accepts `args: {detail:'summary'}` and full
  discovery filtered with `args: {names:[...]}`. Both use the installed declarations; the
  default full SDK/CLI/HTTP discovery contract is unchanged. This matters in the
  fixture: 80 commands and about 376 KB of full catalog data. Oversized tool
  outcomes return an actionable structured error, never partial JSON.

The adapter receives bounded context with accepted project identity/revision,
selected IDs and output ports, physical/presentation time, visible view titles,
registered command availability, used model assumptions and current diagnostics.
It can inspect additional details through the gateway. All mutations require
current expected identity and idempotency keys; the host never executes project
source. Ordinary reversible edits commit immediately with a summary and Undo.

Stop synchronously revokes the grant and owned F04 work before awaiting native
interruption. Late callbacks, tool outcomes and replays cannot resurrect it.
Completion, failure, disconnect and project-generation changes revoke authority
as well. A stopped native turn can take time to wind down. Committed edits stay
until a separate Undo. A failed interrupt closes the native connection rather
than granting its old work the next turn's authority.

Browser Submit and Stop carry their originating session and request/turn IDs.
If Stop arrives before its matching submit, the bridge remembers that request
as cancelled within a bounded ledger. Delayed actions from a prior session or
turn cannot launch cancelled work or stop later work. Closing an observing tab
detaches it without cancelling a shared turn.

## Real verification

Tested with **Node 24.22.1**, **Codex CLI 0.166.0-alpha.5.1**, **macOS 27.0.1
arm64**, **Chrome 156.0.8078.80**, **Playwright 1.62.1**, **Three.js 0.187.0**,
headless WebGL2/SwiftShader. Installed executable on the test machine:
`/Applications/ChatGPT.app/Contents/Resources/codex-cli/CodexCLI.app/Contents/MacOS/codex`.
`codex login status` reported existing ChatGPT authentication; `account/read`
confirmed it. The runtime selected its configured `gpt-6-astra` model. No API
key, account email or native authentication payload entered the browser.

The [real browser harness](../../scripts/verify-agent-browser.mjs) passed **six
interaction groups** against an isolated workspace. Its browser typed prompts;
there was no mock adapter, prebuilt construction recipe or direct graph edit
standing in for the agent. Browser geometry was arranged before acceptance.

1. The browser selected and connected Codex; the native handshake confirmed its
   real thread, dynamic tools and permission controls.
2. Ctrl+Enter submitted a request. The agent discovered schemas, inspected the
   graph, and committed three moving points, a collection, magnitude map, mean
   reduction, scene/plot bindings and a visible plot in one undoable transaction.
   The plotted Value equaled the worker result: **2 m at 0 s**, independently
   expected from initial positions `[2,0,0]`, `[0,2,0]`, `[0,0,2]` metres.
3. A second request created `agent-second-plot` bound to `agent-magnitudes`.
   `agent-derived-plot` stayed bound to `agent-mean`. The browser displayed both.
4. The agent removed only the second plot. Its source, mean view and scene
   survived. One browser Undo restored the removed view at a fresh revision.
5. Browser Stop interrupted a fourth real turn; normalized state moved from
   working through cancelling back to ready. The accepted graph revision did
   not change.
6. Disconnect closed provider state; the transcript stayed visible and physical
   playback advanced. No provider was needed for this computation or rendering.

The run recorded **24** gateway calls, including **three accepted transactions**.
Two render reads received `SUPERSEDED` while the viewer refreshed the same F04
runtime; subsequent reads succeeded without repeating any write. Zero unexpected
browser errors or dialogs. Evidence in ignored `.local/f08-qa/`: `report.json`,
`connected.png`, `constructed.png`, `independent-plots.png`, `undo.png`,
`stopped.png`, `disconnected-playback.png`. The restarted normal workspace was
also checked for real readiness and left disconnected, with its clean fixture.
An additional real browser run verified correlated Submit/Stop, closing a second
tab during active inference, and reloading the disconnected transcript with Send
disabled. The project stayed at revision zero. Its receipt and screenshot are in
`.local/f08-qa/lifecycle/`.

## Deterministic verification

`bash scripts/node.sh --test` passed **419 tests**, zero failures/skips: all 361
prior tests plus 58 F08 checks. Output: `.local/f08-qa/test-results.txt`.
The new tests exercise native protocol framing/configuration and permission
translation, bounded context, isolated startup without astronomy, streamed
text and duplicate events, failed/expired auth, pending inputs and permissions,
reconnect, concurrent Stop/submit, actual gateway job cancellation, stale loads,
late-write rejection, HTTP boundaries, and browser client recovery. Authentication
failure, native permission prompts, malformed frames and late delivery are
deterministically injected; no real credential failure or escalation was induced.

The [mock browser harness](../../scripts/verify-agent-ui-browser.mjs) passed four
groups with zero errors, including deny-only native permissions, input answers,
tool-driven plot creation, Undo, Stop, failed auth, drafts and disconnected
playback. Its reports and inspected screenshots are in `.local/f08-ui-qa/`.
The F07 browser regression passed all four groups without errors/dialogs. F06
passed all eight desktop/narrow groups; its 20 expected read conflicts matched
16 `SUPERSEDED` and four `STALE_RESULT` responses, with zero unexpected errors.
These are browser/software-renderer checks, not hardware GPU certification.

## Boundaries and next work

- Native authentication is runtime-owned. The host consumes public protocol
  events and normalized tool summaries; it does not read auth files, retain raw
  stderr, import ChatGPT chats or persist credentials. Visible transcript and
  provider state are distinct. Reconnect creates a new ephemeral thread; resume
  is explicitly unsupported. Transcript/events and deduplication are bounded,
  in-memory companion state. An already-connected provider may use its network
  for inference; disabling native tool network access does not make inference offline.
- The adapter verifies read-only sandbox, native network disabled, separate cwd,
  no unexpected runtime workspace roots or project instruction sources, shell
  and unified execution disabled, and inherited MCP servers disabled. A merged
  empty MCP table was insufficient on this build, so it disables each inherited
  entry and rechecks effective configuration. Its code-mode host dispatcher
  **must remain enabled** for native dynamic calls. This was confirmed by an
  initial failed tool attempt, a real 80-command discovery, and the successful
  browser construction. No arbitrary code is passed into the project gateway.
- Default native policy is deny. Ask mode surfaces only choices the adapter
  supports; Codex native escalation is deny-only. Ordinary scoped scene edits
  continue without redundant approval. Secret-input questions are rejected.
  Read-only mode on this installed protocol lacks restricted readable roots;
  do not claim full filesystem-read isolation. The executable and installed
  extensions are trusted, and loopback is not authentication against other
  local processes. The adapter checks its controls at connect and fails closed
  when they cannot be established.
- The approved logo, BSD notices, pinned dependencies and existing exoplanet SDK
  remain unchanged. No portable project package, runtime installation, general
  ACP adapter or provider resume feature is claimed. F08 acceptance has no
  remaining blocker on the tested installation. **F09 portable projects is next.**
