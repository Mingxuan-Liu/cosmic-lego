# F02 — Scientific dataflow handoff

Implemented and checked **2026-11-03** on the F01 kernel. Generic moving points,
scalar/vector fields, reusable arithmetic, selections and explicit adapters run
without astronomy modules. This delivers synchronous dataflow, not the F03
extension registry or F04 stateful runtime.

## Public interfaces and graph contract

`src/dataflow/index.js` exports `createDataflow`, `DEFAULT_LIMITS`, `value`, `unit`,
`validateValue`, `descriptorOf`, `sameDimensions`, `checkPort`, `convertValue`,
`transformValue`, `binaryValue`, `mapValue`, `reduceValue`, and `fieldValue`.

```js
const flow = createDataflow({ models, adapters, limits });
const project = new Project({ validators: flow.validators });
const draft = project.begin();
const author = flow.author(draft);
// Create definitions through author methods, then draft.accept().
const result = flow.evaluate(project, nodeId, {
  port: 'value', time: { value: 2, unit: 's' },
});
```

The facade returns actual F01 handles. Methods are `constant`, `component`,
`select`, `field`, `arithmetic`, `map`, `reduce`, `adapt`, `update`, and `remove`;
exact signatures and runnable examples are in
[the scientific-dataflow guide](../scientific-dataflow.md). Inputs accept handles,
ID strings or `{node:handleOrId,port}`; bare references use output port `value`.
The sole F01 API extension is `draft.idOf(handleOrId)`, exposing existing kernel
ownership/generation checks so the facade does not implement competing identities.

All calculations use F01 node kind `calculation` and these types:

| Type | `node.data` |
| --- | --- |
| `dataflow.constant` | `{value: normalizedValue}` |
| `dataflow.selection` | `{mode:'fixed',element,inputs}` or `{mode:'live',query:{type,port},element,inputs:{}}` |
| `dataflow.field` | `{indices,inputs}` |
| `dataflow.arithmetic` | `{op,inputs,comparison?,alignment?}` |
| `dataflow.map` / `dataflow.reduce` | `{op,inputs}` |
| `dataflow.adapt` | `{adapter:registeredId,inputs}` |
| Injected component/model type | `{parameters,inputs}` |

`inputs` maps a slot to `{port:outputPortName}`. The source node is recorded in
`node.references['input.' + slot]`; `dependsOn` must equal the distinct input-node
IDs. Acceptance rejects disagreement between these three declarations. Raw F01
transactions, updates, undo/redo and load use the same scientific hooks when
`flow.validators` is installed. Scientific drafts can remain incomplete until
acceptance, just as in F01; auto-inferred selection contracts need a source already
described in the draft, or an explicitly supplied `element` contract.

`flow.inspect(graph)` returns `{valid,errors}`. `flow.dependencies(graph,id)`
reports sorted direct effective computational inputs, including live membership.
`flow.evaluate` rechecks the scientific graph even if the caller constructed its
Project without scientific hooks. It consumes accepted Projects, not drafts.

## Exact scientific value and port schemas

Normalized values have all of these fields:

```js
{
  kind: 'scalar' | 'vector' | 'collection' | 'field' | 'series',
  shape: [],          // scalar []; vector [3]; containers [N] or [N,3]
  data: 1,            // matching number/array; null only at missing scalar leaves
  unit: { symbol: 'm', dimensions: { length: 1 }, scale: 1 },
  meaning: 'quantity-meaning',
  reference: null,    // or a nonempty semantic reference identifier
  frame: null,        // or {id,kind:'position'|'direction'|'display'}
  normalization: null,// or {reference,definition}, both nonempty strings
  coordinates: null, // series: {kind:'time',unit,values:[t0,t1,...]}
                     // field: {kind:'space',unit,frame,values:[[x,y,z],...]}
  objectIds: null,    // collections: distinct nonempty source IDs, length N
  time: null,         // or {value:finiteNumber,unit:normalizedTimeUnit}
  metadata: {
    warnings: [{code,path,message}],
    approximation: ['description'],
  },
}
```

`value(spec)` infers shape if absent and supplies null context/empty metadata
defaults. Units and quantity meaning must be explicit. Scalar and vector fields
retain spatial coordinates independently of value-vector frames. A field's
locations use length units and a position frame. Time-series coordinates use time
units and strictly increasing finite numbers. Coordinate counts and collection
identities must match data rows. Wholly missing vector rows use `[null,null,null]`
with a declared vector shape. Missing values are labeled, never zero-filled.

A port descriptor requires `kind`, `shape`, `unit`, `meaning`, `reference`, `frame`,
and `normalization`. It optionally constrains `coordinates`, `time` and `objectIds`.
`null` in a container shape means a variable length; context null means declared
absence, not a wildcard. An omitted optional context field imposes no equality
requirement. `descriptorOf(value)` includes concrete optional context fields.

`checkPort(source,requirement)` returns diagnostics. It checks both declarations,
shape, units, meanings, references, frames, normalization and specified sampling
context. Compatible dimensions with differing scales yield
`UNIT_CONVERSION_REQUIRED` at model connections; the author must insert a real
adapter. Matching dimensions cannot relabel another quantity as an observable.

Units support named `1`, `m`, `km`, `cm`, `s`, `min`, `h`, `kg`, `K`, `m/s`,
`km/s`, `m/s^2`, plus explicit multiplicative derived descriptors. Supported
dimension keys are length/time/mass/temperature with integer exponents −12…12.
Scale is finite, positive and relative to SI. Known symbols cannot contradict
their built-in dimensions/scales. Offset units, automatic compound-unit parsing,
astronomical coordinates and astronomical time standards are outside scope.

Value/reference/frame/normalization IDs describe semantic context; they may name
external datasets or comparisons. They are not implicit graph ownership edges.
Graph inputs remain explicit F01 references. Collection object IDs identify the
selected graph nodes.

## Arithmetic, frames, membership and alignment

- `add`/`subtract` convert compatible units to the left unit and retain signed
  values. Different meanings or references require an explicit
  `{comparison:{meaning,reference}}`, producing `UNVALIDATED_COMPARISON`.
  This never bypasses unit, frame, normalization, time or sampling constraints.
- `multiply`/`divide` derive dimensions and support scalar scaling. Vector
  dot/cross/tensor products are not guessed. Zero division and non-finite results
  return errors. A neutral scalar factor preserves contextual normalization in
  either multiplication order. Products of two normalized quantities and a
  normalized denominator require an explicit adapter defining output normalization.
- Positions are affine coordinates: position−position gives displacement;
  position±direction gives position. Position+position and direction−position
  reject. Frame IDs must match. Rigid adapters implement proper orthonormal 3×3
  rotation and optional length translation, translating positions only.
  Directions rotate; field locations can translate independently of directional
  field values. Display coordinates cannot become physical positions by relabeling.
- `map('magnitude')` maps vectors to scalars; `map('abs')` is explicit scalar
  absolute value. `reduce('sum'|'mean')` accepts scalar per-object collections
  and uses compensated summation. Empty or missing reductions do not invent zero.
- `field(source,indices)` selects distinct in-range rows in the requested order,
  preserving coordinates, units and metadata. It is field selection, not a new
  physical solver or observable.
- Fixed selections store explicit input IDs/ports. Live selections store an
  exact type/port query and reevaluate membership against each accepted graph.
  The saved element contract fixes units/context; compatible member units convert
  to it. Inferred element references are null, and distinct members retain
  `objectIds` plus a grouping warning. An explicitly required non-null element
  reference must match every member and is retained.
- Live dependencies are expanded into an effective graph checked by F01's
  reference/cycle validator. They participate in evaluation ordering/cycle
  detection without rewriting authored definitions. F01 dependency queries still
  report authored edges; use `flow.dependencies` for effective live inputs.
  Live queries do not create persistent ownership references for cascade removal.
  Removing a member can leave a valid empty live selection. Fixed references retain
  the usual reject-or-explicit-cascade behavior.
- Collections align by object ID, not array index. Fields require matching
  positions in compatible coordinate units and the same frame; there is no spatial
  interpolation. Time-series arithmetic defaults to matching physical sample
  coordinates. `{alignment:{policy:'linear',target:'left'}}` explicitly interpolates
  the right series onto left coordinates and emits `INTERPOLATED`. It neither
  extrapolates nor bridges missing samples. Alignment uses a small floating-point
  tolerance (16 machine epsilons scaled to the compared magnitudes).

## Result envelope and time

```js
{
  identity: {projectId,generation,revision},
  producer: {nodeId,port,implementation:{id,version}},
  request: {time:{value,unit}},
  value: normalizedValue, // null when invalid
  valid: true,
  diagnostics: [{code,path,message,severity:'warning'}],
  metadata: {
    approximation: ['description'],
    sampling: {policy:'declared-coordinates',coordinates,time},
    implementations: [{id,version}],
    work: 0,
  },
}
```

Failure results use `valid:false`, null value and diagnostics. Producer
implementation may be null if unavailable; malformed requests may have null
request, and failed evaluation may have incomplete sampling metadata. Consumers
must check validity before using values. Warnings can coexist with valid values,
including explicit missing data in a displayed field. The interpolation sampling
policy is `linear-right-to-left` when it contributes to a result.

Request defaults are output port `value` and physical time 0 seconds. A non-null
snapshot timestamp must match the requested physical time in compatible units.
Timeless constants, fields and their collections remain timeless; no request time
is invented for them. Series carry independent declared sample coordinates.
This evaluator does not advance numerical state or infer time from frame rate.

All results retain F01's full identity triple. Callback mutation, including loading
the same saved graph, produces `STALE_RESULT`. Callers must still reject previously
returned results after any later identity change. Memoization is per evaluation;
there is no cross-request cache or asynchronous job manager.

## Trusted injection and limits

Models are supplied as `{type:{implementation:{id,version},outputs(node),
inputs?(node),validate?(node),evaluate({node,inputs,request})}}`. Output/input
functions return maps of port descriptors; evaluation returns a map of Values.
Optional `validate` returns acceptance-error diagnostics. Adapter records are
`{implementation:{id,version},input:descriptor,output:descriptor,apply(value)}`.
Actual returned ports and Values are checked against declarations. Built-in
calculations identify their implementation as `cosmic-lego.dataflow`, version `1`.

Functions receive detached frozen data, must be pure/synchronous and cannot be
chosen by stored code or imported by project paths. Promises fail closed.
This is trusted-code injection, not a registry or a sandbox. Arbitrary callback
CPU/side effects are not preempted; F03/F04 must develop that lifecycle separately.
Models and adapters must propagate relevant warnings/approximation metadata.

Defaults: **256 project nodes**, **10,000 numeric/missing entries per value**
(data plus coordinates), **100,000 evaluation work units**, and **128 nodes per
computational path**. Positive safe-integer overrides are accepted. Work charges
nodes and input/output entries, including every consumer of a cached collection.
Repeated reductions cannot evade the budget by producing tiny outputs. Shape
limits are checked before downstream descriptor probes allocate sample arrays.
These are deterministic graph-work limits, not a wall-clock or process-memory cap.
Standalone arithmetic helpers do not impose a flow environment's workload budgets.
