# F10 handoff — authored timelines and reproducible local delivery

Implemented and verified locally on 2026-11-03. The demonstration holds nine
moving points at the same physical time and compares two velocity configurations.
The camera moves during the hold. The readout reports the mean of the nine
distances from the origin in metres. The temperature colors and velocity arrows
come from the two F05 field bindings. A separately sampled seeded accumulator
checks stateful replay. These are generic software fixtures. [Recipe](../../examples/authored-timeline.mjs)

## Try the delivery

Create the example in an unused slot, launch its player, or import the file into
the workspace and open the authored player from **Project**. The standalone
player needs Node.js 20+ and a WebGL 2 browser. The packaged copy includes the
trusted runtime, fixture models, renderer and notices for offline use.

```sh
bash scripts/node.sh examples/authored-timeline.mjs --directory .local/timeline-input
bash scripts/node.sh scripts/timeline-server.mjs --project .local/timeline-input/motion-study.json --port 0
```

The delivery CLI accepts `export PROJECT NEW_DIRECTORY --start S --end E --fps F
--width W --height H` or `package PROJECT NEW_DIRECTORY`. The exporter can use a
locally installed Playwright via `COSMIC_LEGO_PLAYWRIGHT` and Chrome via
`COSMIC_LEGO_CHROME`. The receiving player does not need Playwright. The
[authoring and delivery guide](../authored-timelines.md) includes full commands.

## Time, configurations and editing

- `createTimeline({id,title,duration})` creates an authoring handle.
  `track(...)` and `boundary(...)` return handles with `set()` and `remove()`.
  `apply({command,args})` accepts data-only track, boundary and removal commands.
  `snapshot()` returns an immutable definition. `editTimeline(definition)`
  reopens it for authoring. Pass the definition as `timeline` on F09 manifest
  creation or workspace save/export. [Authoring API](../../src/timeline/definition.js)
- Presentation time is seconds from the start. Physical seconds and world-space
  camera eye/look target use linear key interpolation. Values hold after the
  final key. Visibility, annotations and panel emphasis change at their key
  times. A missing physical track maps presentation seconds directly to
  physical seconds. Equal physical keys hold the science while presentation
  continues. Decreasing keys seek toward earlier scientific samples.
- Boundaries sort by presentation time, then authored order at a shared time.
  Each boundary runs its operations in one F01 draft through the same F07
  command catalogue and installed validators. A frame at the boundary sees all
  transactions at that time before presentation tracks are applied. New nodes
  and relationships require stable explicit IDs. The authoring graph and its
  Undo history are never used as a destination. These are comparisons of
  separately specified configurations. A physical impulse would require a model
  with that meaning. [Configuration compiler](../../src/timeline/configurations.js)
- The container remains `cosmic-lego.project` version 1. Its timeline extension
  accepts the original null or version-0 metadata and the new version-1
  definition. The file records the graph hash and exact transitive model and
  factory implementation pins of every boundary configuration. This includes
  extensions first introduced inside events. Opening recompiles each boundary
  and compares the pins before replacing the live workspace. Authored data is
  bounded to 64 KiB, 64 tracks, 512 total keys, 16 boundaries and 32 operations
  per boundary. [Portable format](../../src/portable/format.js)

## Evaluator, renderer and export

`await createTimelineEvaluator({manifest, registry, binding, layer, registryModule})`
owns a frozen snapshot and isolated configurations. `await evaluate(seconds)`
returns authored time, requested physical time, project identity, configuration
hash and boundary prefix, scientific results with achieved times, a compiled
F06 snapshot, presentation annotations and warnings. `dispose()` revokes
pending work. Each frame requests F04 at the mapped physical time. A stateful
model replays forward from its initial conditions, even when a user seeks
backward. The seeded fixture reports its last complete lattice step on
off-grid requests. [Evaluator](../../src/timeline/evaluator.js)

The workspace and offline host share `GET /api/timeline` and
`POST /api/timeline/frame`. GET returns the title, duration, snapshot identity
and boundary times. POST accepts `{time,snapshotId}` and returns the evaluated
frame. A changed workspace returns a stale-snapshot error to the earlier viewer.
The standalone host is read-only and fixes its trusted registry at startup.
Interactive controls and the export capture surface draw the same frame through
the shared stage and F05 adapter. The renderer acknowledges the project,
configuration, clocks and viewport after assets, fonts and drawing are ready.
[Host](../../scripts/timeline-http.mjs) · [Player](../../demo/timeline/app.js)

`exportFrames({manifest,directory,schedule,signal?,onFrame?})` snapshots input
before asynchronous work, launches an isolated loopback player and schedules
`start + i/fps` through the specified end. A grid-aligned endpoint is included.
Individual frame sidecars contain the actual scientific Values, their hashes,
requested and achieved times, normalized settings, configuration, warnings,
renderer, assets and PNG hash. The sequence index binds these files to one
project and frame schedule. A committed frame requires a complete PNG and JSON
sidecar. An interrupted run leaves the recorded prefix usable. Resume by
starting a new output directory. [Exporter and packager](../../src/timeline/export.js)

## Reproducibility and limits

The acceptance criterion for the fixed generic implementation is equality of
configuration, units, scientific values, sampled times and asset content IDs.
The independent analytic comparison permits absolute rounding error up to
10⁻¹² m. Actual delivered PNGs have individual byte hashes. Across GPUs, browsers
and installed fonts, matching scientific results can produce different pixels.

Interactive display throughput depends on worker speed. The export waits for
every scheduled sample. Version 1 has one active camera, discrete topology,
bounded F04 replay and local generated assets. It delivers PNGs and a Node/WebGL
player. F11 can exercise the shared path with an independent construction and
registry. F12 still owns domain migration. An additional domain would need a
trusted player composition root including its pinned implementations and notices.
