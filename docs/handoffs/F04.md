# F04 — Computation runtime handoff

Implemented **2026-11-03** over F01–F03. Analytic random access and basic stateful
initialization/advancement/extraction/checkpoint/restore now run in disposable
Node workers. The model supplies numerical algorithms; the runtime schedules and
checks them. The exoplanet prototype remains unchanged and separate until F12.

## Entry points and ownership

`src/runtime/index.js` exports `createRuntime` and `RUNTIME_LIMITS`. See
[the runtime guide](../computation-runtime.md) and the executable
[author example](../../examples/computation-runtime.mjs).

```js
const runtime = createRuntime({
  registryModule: new URL('./installed-composition-root.mjs', import.meta.url),
  limits: { maxSteps: 10000, maxWallMs: 5000 },
});
const job = runtime.submit(project, nodeId, {
  port: 'value', time: { value: 2, unit: 's' }, mode: 'auto',
  settings: { [nodeId]: { step: 0.25 } },
});
const result = await job.promise;
await runtime.dispose();
```

The trusted host file exports synchronous `createRegistry()`, returning the actual
shared `ExtensionRegistry` with installed callbacks. Only runtime construction
selects this explicit local file URL. Graphs, manifests, requests, checkpoints and
source strings cannot select imports. There is no function serialization, code
evaluation, downloader or provider connection. Workers dynamically load the
trusted composition root; shared modules never import fixture/domain packages.

`submit` requires an accepted F01 `Project`, snapshots its data and identity, and
returns `{id,promise,cancel(),status,progress}`. Request fields are `port`, `time`,
`mode`, `settings` and optional `checkpoints`. Malformed host/request data throws;
computation failures resolve an invalid result with diagnostics and no value or
checkpoints. Status is queued, running, completed, cancelled or failed. Progress
is detached data with phase, component, physical time, step and work counts.

One job is active per runtime. A new submission supersedes the previous job;
the newest queued request starts after previous workers have terminated. There
is no unbounded queue or pool. `setProject(project)` explicitly invalidates prior
project work; `submit` also selects its project. `dispose()` cancels and waits for
worker termination. Always dispose runtimes after use.

Model states belong to a job and are never stored as mutable F01 definitions.
Successful checkpoints are cached by component within the same identity triple,
bounded by count and bytes. New successful results replace that component's
checkpoint; unrelated cached components remain available. Failure/cancellation
does not replace successful checkpoints. Any accepted edit or load clears the
automatic cache conservatively, including a presentation-only revision. Explicit
resume can still reuse a compatible scientific checkpoint after such an edit.

## Registry and lifecycle contracts

Scientific manifests now normalize legacy analytic/stateless declarations to
`runtime:{paths:['analytic'],settings:closedEmptyObjectSchema}`. Explicit runtime
metadata is required for `science.evaluation.mode:'stateful'|'hybrid'`:

```js
runtime: {
  paths: ['analytic', 'stateful'], // hybrid; either single path also supported
  settings: closedObjectSchema,
  stateful: {
    initialTime: { value: 0, unit: 's' },
    sampling: 'exact', // or 'at-or-before'
    random: { algorithm: null }, // or a declared generator identifier
  },
}
```

Runtime paths must agree with scientific mode. Stateful metadata exists exactly
when that path exists. Time units reuse F02; the initial time must be finite in
seconds. Settings use the existing bounded schema/default validator. Only settings
for the requested dependency closure are required/validated. Known unrelated
overrides can be carried in a project-level settings map; unknown IDs reject.

Analytic implementations retain `evaluate({node,inputs,request,settings})`.
Stateful implementations additionally supply all these synchronous callbacks:

| Callback | Input and return |
| --- | --- |
| `initialize` | `{node,inputs,settings,request}` → `{state,random,time}` at declared initial time. |
| `advance` | `{node,inputs,settings,state,random,time,targetTime}` → `{state,random,time,done}` for one bounded model-owned step. |
| `extract` | `{node,inputs,settings,state,random,time,request}` → map of F02 Values at achieved time. |
| `checkpoint` | Same snapshot context as extraction → finite JSON payload. |
| `restore` | `{node,settings,checkpoint:payload}` → `{state,random,time}`. |

State and payload are data; random state is null for deterministic models or
`{algorithm,state}` matching the manifest's generator identity. A seed alone is
not continuation state. Arguments are detached/frozen; callback outputs are
copied and checked. Async/generator lifecycle functions reject registration;
Promise-returning synchronous functions fail at invocation. Callbacks must be
pure apart from their explicit state transition, with bounded individual steps.

`registry.bind({execute})` injects the trusted scheduler into the existing F02
evaluation path, using `{manifest,implementation,node,inputs,request}`.
`binding.computations` exposes frozen trusted records to the scheduler; discovery
remains data only. Direct binding evaluation uses the analytic path for hybrids
and returns `RUNTIME_REQUIRED` for stateful-only models. The F03 reference-case
harness remains synchronous; stateful evidence comes from runtime tests. Tests
still do not certify scientific review or promote manifest status.

## Time, dependency snapshots and backward seeking

`mode` selects the requested root's path. Auto selects analytic when present;
dependencies also use their own automatic path. Explicit unsupported paths fail
with `CAPABILITY_UNSUPPORTED`. F02 built-in calculations remain analytic operations
over their dependencies; they have no hidden stateful integrator.

Physical seconds are canonical inside the scheduler; the result request retains
the requested value and normalized original unit. Presentation frame rate is not
an input to integration. F02 graph analysis supplies effective dependencies,
including live selections, and rejects computational cycles before work starts.
Ordinary relationship cycles remain allowed. No alternate graph/units engine was
introduced, and no dataflow source changes were needed for F04.

Initialization reads inputs at initial time. Each advancement reads upstream
scientific inputs at the step's starting time; an extension can declare stronger
input conditions (the deterministic fixture requires a timeless rate). Model
outputs are shared across ports at one node/time while retained in bounded
caches. The model must document the numerical meaning of its input sampling;
the runtime does not infer an integrator or interpolate intermediate states.

Advancement cannot move backward or overshoot its target. An unfinished step must
make time progress. Exact-sampling models must reach the target; at-or-before
models can finish earlier and report their actual time. Stateful outputs must
explicitly carry that time. Derived snapshots require compatible achieved times
across their stateful dependencies. Mismatches return `SNAPSHOT_TIME_MISMATCH`
with diagnostics, never silently relabeled values.

Results retain the F02 envelope and add `checkpoints` and `metadata.runtime`:
requested/achieved times, selected path, global steps/work, scientific input
identity, settings, stateful component identities/random state/sampling/seek
strategy, job ID and elapsed milliseconds. A result at an earlier declared sample
has `TIME_APPROXIMATION`, explicit sampling policy and its true Value timestamp.
Warnings/approximation metadata from inputs survive dependent computations and
state transitions. Failure returns null output; it does not publish a valid
partial trajectory.

Backward seeking restores a compatible checkpoint at or before the target, or
initializes and replays forward. The cache stores the latest checkpoint per node,
so a cached future checkpoint commonly causes reset/replay. Earlier compatible
checkpoints may be supplied explicitly. There is no reverse integration, numerical
Undo, or promise of constant-time seeking. Replay consumes the same budgets.

## Checkpoint format and identity

Checkpoint version 1 is plain data:

```js
{
  schemaVersion: 1, identity: {projectId,generation,revision}, nodeId,
  implementation: {id,version,build}, inputIdentity: 'sha256:...',
  settings, time, random, metadata: {warnings,approximation}, payload,
}
```

`inputIdentity` hashes canonical component definitions, effective transitive
dependency identities, chosen lifecycle paths, declared implementations and
resolved numerical settings. Presentation nodes outside that dependency closure
do not change the hash. Hashes identify declared inputs; they do not authenticate
code, certify payloads, or account for untracked external/global state. Models
must represent authoritative data/settings through their declared inputs.

Automatic resume requires the same live project/load/revision token. Explicit
`checkpoints:[...]` may rebind a compatible checkpoint to a fresh generation or
revision of the same project ID. Implementation/build, scientific inputs, settings,
and the requested stateful closure must match. The model validates/restores its
payload; the restored time and full random state must match the envelope. Newly
produced results/checkpoints receive the current identity. Import never changes
accepted graph state or grants write authority. Unknown/incompatible checkpoints
fail visibly rather than silently restarting; automatic cache misses may restart.

## Cancellation, limits and measured evidence

The parent watches identity changes at intervals no greater than 25 ms, and checks
again before publication. Cancellation, supersession, stale identity and deadlines
immediately settle an invalid job and request worker termination; late messages
are ignored. `dispose()` waits for actual exit. Only successful current jobs can
update cached continuation state. Existing accepted graph edits are unaffected.

The worker boundary was checked against [Node's official worker documentation](https://nodejs.org/docs/latest-v24.x/api/worker_threads.html)
on 2026-11-03 (served 24.22.2); execution used bundled **Node 24.22.1**.
Termination stops JavaScript as soon as possible and completes asynchronously.
Workers are trusted execution, not an OS sandbox; native/external side effects
cannot be rolled back. The V8 old-generation limit is not a whole-process or
external-buffer memory cap. These APIs were exercised with actual busy JavaScript.

Defaults: 10,000 advance calls, 1,000,000 runtime work units, 1 MB aggregate
memoized state, 2 MB checkpoints, 128 retained state snapshots, 5 s wall time,
2 MB graph, 4 MB result/scientific-cache bounds, 64 MB worker V8 old generation,
and 25 ms progress interval. Byte limits use UTF-8 JSON sizes. F02's existing
256-node/10,000-value/100,000-work/128-depth limits also apply to each evaluation.
Scientific read/output caches evict old entries; state memo overages fail.
Work counters cover lifecycle calls and F02 evaluation work, not arbitrary
callback instruction counts; deadlines/worker termination handle busy callbacks.

Executed evidence includes:

- `bash scripts/node.sh --test --test-reporter=spec`: **203 checks passed**, zero
  failures/skips (167 prior tests, 35 new tests and one support-module load).
  The executable example, source syntax checks and `git diff --check` pass.
- Deterministic fresh/analytic/sequential/checkpoint-resumed results all equal
  **6 at 2 s**; a fresh run uses eight steps, a 1 s checkpoint resume uses four.
- Seeded fresh/sequential/resumed values equal **−0.7182601829990745** at 2 s;
  LCG state is **2355140353**, draw count **8**. Backward replay matches fresh
  early sampling. A 1.1 s request reports its 1 s achieved sample explicitly.
- A 24→60 fps presentation edit leaves the scientific value and input identity
  unchanged. Presentation independence is checked numerically; no UI changed.
- One local integration run measured four parent timer ticks during an entered
  busy callback: cancellation settled in **0.128 ms**, termination/disposal in
  **2.579 ms**. A **250 ms** deadline returned in **251.154 ms**. These are local
  observations, not guaranteed latency bounds or browser frame-rate measurements.
- The deterministic checkpoint occupied **704 UTF-8 JSON bytes**. One example
  run took about **45 ms** for analytic worker startup/evaluation, **63 ms** for
  stepped work and **41 ms** for checkpoint resume. Per-job worker startup is
  intentional here; this is not yet a high-throughput frame-rendering scheduler.
- Tests cover lifecycle/path contracts, real CPU cancellation, deadline/step/work/
  state/checkpoint/result bounds, progress failures, stale edits/loads/project
  switches, incompatible checkpoints, warnings, coherent derived time, colon-safe
  cache keys and dependency-scoped settings. An isolated worker runs with only
  copied shared layers and a locally injected fixture; no astronomy files exist.

## Integration requirements and remaining scope

- **F05/F06:** consume current identity-tagged scientific snapshots, requested and
  achieved time, diagnostics, units and metadata. Do not use display frame rate
  as a numerical step. Connect the Node runtime through the future application
  host; browser renderer/shell integration is not implemented here.
- **F07/F08:** route jobs through existing graph/gateway authority and bind turn
  cancellation to job cancellation. Stopping work revokes future results; Undo
  remains a distinct graph operation. The worker host file is trusted host setup,
  never a conversation/project field.
- **F09:** preserve initial settings/inputs and optional versioned checkpoint
  payloads/random state. Use explicit compatibility checks on reopen, then fresh
  identity tokens. Current JSON checkpoint round trips are not an atomic portable
  project archive or a migration implementation.
- **F10:** schedule physical sample coordinates explicitly, retaining true achieved
  coordinates when a stateful model cannot land exactly. Rendering/export cadence
  is separate. A model requiring unsupported coupling must supply an explicit
  solver/adapter instead of bypassing graph cycles or inventing time alignment.

There is no worker pool, GPU/distributed computation, implicit state interpolation,
general coupled solver, browser runtime transport, renderer, persistence archive,
or domain migration. The approved logo, BSD-3-Clause license, dependencies and
existing astronomy implementation remain unchanged. Next task: **F05 scene/assets**.
