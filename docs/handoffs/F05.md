# F05 — Scene and assets handoff

Implemented **2026-11-03** over F01–F04. Generic moving-point collections and
scalar/vector fields now render in a navigable browser scene. The public handles,
accepted project, scientific Values, registry and worker runtime remain the
authorities. The existing astronomy prototype remains separate until F12.

See the [scene guide](../scene-and-assets.md), executable
[author example](../../examples/scene-and-assets.mjs), and trusted
[composition root](../../examples/fixtures/scene-registry.js).

## Scene authority and public interfaces

`src/scene/index.js` exports `registerSceneExtensions`, `createSceneLayer`,
`sceneExtensions`, `bindingExtensions`, `sceneAuthor`, and `SCENE_LIMITS`.
The composition root installs scene definitions into the existing F03 registry
with host capability `scene.data`; shared modules do not import fixtures or domains.

Create an F01 `Project` with `layer.validators`. `layer.author(draft)` offers
`root`, `group`, `camera`, `geometry`, `texture`, `material`, `mesh`, `points`,
`polyline`, `vectors`, `label`, `bind`, `update`, `duplicate`, `reparent`, and
`remove`. These return ordinary F01 handles and use its acceptance, references,
identity, rejection, cascade and history rules. Duplicate copies one instance and
its incoming scientific bindings, retaining asset/source references. Group copies
are shallow. The renderer's mutable graphics objects never become project handles.

Presentation instances contain IDs, parent references, visibility, translation,
Euler XYZ rotation and positive scale. Groups compose display transforms.
Cameras support perspective and orthographic projection, target, near/far,
field of view and span. Modest geometry comprises sphere, box, plane and indexed
or unindexed triangles. Points and vector arrows use instancing. Polylines and
plain-text labels complete the initial primitive set.

`layer.sources(project)` lists distinct required scientific node/port pairs,
including scientific inputs to registered asset factories. Obtain their current
F04 results at one physical time, then call:

```js
const snapshot = await layer.compile(project, {
  results, time: { value: 2, unit: 's' }, capabilities: adapter.capabilities,
});
if (snapshot.valid) adapter.apply(snapshot);
```

The detached frozen result is
`{valid,identity,time,nodes,assets,bindings,diagnostics}`. Failures have empty
drawable/asset arrays and visible diagnostics. Compilation checks the full
project/generation/revision token before publication, Value validity, producer
implementation and output descriptor, consumer port, and achieved physical time.
Inputs are detached before asynchronous hashing. Missing snapshots fail with
`RESULT_REQUIRED`; scene compilation never silently evaluates scientific code.

F03 `binding.produce(project,id,{time,results})` now supports supplied result
envelopes for this purpose. Omitting `results` preserves the earlier synchronous
F03 API. Supplying it, including an empty array, forbids implicit evaluation.
`binding.visuals` exposes installed trusted visual/asset records, analogous to
`binding.computations`. No dataflow/runtime authority was replaced.

## Mapping and physical meaning

Four binding definitions map a position vector, position collection, scalar
field, or vector field into an instance's translation, point array/colors, or
arrow origins/directions. Binding parameters identify source/port, quantity,
source/display units and frames, rigid rotation/translation, position unit,
display scale, and explicit color range/palette. F02 performs dimensional and
frame checks. Current bindings accept named F02 units and unnormalized values;
they do not guess units or normalize arbitrary arrays.

Compiled binding records retain the original Value descriptor (including units,
frame, coordinates, meaning and normalization), producer implementation,
mapping, sampling, warnings, approximations and scalar color meaning. Positions
receive translation; directions receive rotation. Field positions convert
separately from field values. `scale` changes both field origins and vector
components; the vectors node's `vectorScale` changes arrow length alone.

Scalar palettes are `blue-gold` and `grayscale`. Values outside the finite,
positive-width color range clamp with an explicit `COLOR_CLIPPED` count/warning.
Null samples fail rather than becoming zeros. Mapped colors multiply material
colors; a white unlit material preserves the requested palette. Lights and
materials are appearance, not an emission or radiative-transfer law. Scientific
observer/frame models remain computation. Camera and material edits do not alter
numerical Values. Earlier achieved stateful samples must be aligned explicitly;
the scene does not invent interpolation or another scientific clock.

## Assets, identity and resource ownership

Locally supplied asset records contain
`{id,kind,contentId,data,dependencies,provenance,scientificInputs}`. IDs are stable
project handles; content identities are SHA-256 hashes of canonical data and
dependency identities. Source/license metadata remains attached per asset but
does not prevent identical content sharing. Geometry reuse is distinct from
duplicating an instance. Dependencies resolve through declared references, never
paths, network URLs, factory source, shaders or executable project data.

Textures are bounded inline RGBA data. Primitive sphere/box/plane geometry has
UVs; custom triangle UVs, image decoders, external file catalogues and remote
loaders are not implemented. Missing assets and unsupported capabilities fail
explicitly. Trusted registered factory callbacks are still trusted host code.

The adapter stages changes before swapping the current scene. Failed preparation
keeps the prior valid scene. Reference-counted geometry/material/texture caches
use resource kind, content/dependency identity and project/load namespace.
Revisions reuse unchanged resources; replacement or final-user removal disposes
them. New project/load generations release the old namespace and selection.
Per-instance graphics allocations are disposed independently of shared assets.
`dispose()` also releases controls, event handlers, selection helper, renderer and
context. Stats expose live/disposed counts and Three's allocation counters,
without claiming to measure total GPU bytes.

Default compiler bounds: 256 graph nodes, 128 assets, 10,000 instances, 4 MB JSON
asset data and 256 label characters. Author schemas also bound point/geometry
rows to 4,096 and textures to 32×32. Independent renderer limits cap 2,048 nodes,
1,024 assets, 20,000 GPU instances (two per arrow), 200,000 vertices, 4,194,304
pixels per texture, DPR 2 and drawing-buffer axes 8,192. F02/F03/F04 limits still
apply. See the guide for exact contracts and supported limit configuration.

## Adapter choice and navigation

**Three.js 0.187.0**, pinned with its lockfile, supplies this implementation.
Its current primary documentation, npm release metadata and MIT license were
checked on 2026-11-03 before installation. It provides WebGL2 rendering,
instancing, raycasting, textures and OrbitControls. This is an implementation
choice for F05, not a permanent architecture mandate. Links, rationale and the
full MIT notice are in [third-party notices](../third-party-notices.md); the
repository retains BSD-3-Clause and the approved logo's original bytes.

`createThreeAdapter({canvas,onSelect,onCameraChange,onDiagnostic,limits})`
exposes `capabilities`, `apply`, `render`, `resize`, `setCamera`, `frameAll`,
`pick`, `select`, `getCameraState`, `stats`, and `dispose`. Hosts supply sizing,
animation callbacks, accepted snapshots and presentation UI. Render callbacks
draw the latest snapshot; they never integrate a model.

Left drag orbits, right drag pans, and wheel/middle drag zooms. Camera target is
in world display coordinates and determines orientation, superseding its Euler
rotation. Camera position inherits the parent transform; the navigation camera
uses unit scale so nonuniform parent scale does not distort projection.
Navigation survives updates when authored camera and parent world transform
are unchanged. Reset restores the authored view; Fit frames scene bounds.
Near/far clipping remains authored.

Picking takes canvas-local CSS pixels and returns
`{nodeId,objectId?,instanceIndex?}`. Selection follows scientific collection IDs
across reordering, clears when absent, and resets on project/load changes.
Field sample IDs use source ID plus row index; authors must supply persistent
IDs for raw rows that represent reorderable objects. Selection boxes and
navigation are transient view state, not scientific edits.

## Browser host and verification

`scripts/scene-server.mjs` serves the local stage and installed Three modules,
runs F04 Node workers, and compiles current results. It binds only loopback,
checks Host/Origin, bounds JSON requests, serves an explicit resource allowlist,
and checks identity on evaluation/edit publication. Its narrow edit route
supports duplication, removal, marker radius and projection through F01 drafts.
It is an F05 demonstration host, not the F07 gateway. No account or CDN is needed
after installation. The example uses 34 scene nodes, 8 authored assets and 3
scientific bindings, with no astronomy modules loaded.

Run:

```sh
pnpm install --frozen-lockfile --ignore-scripts
node --test
node examples/scene-and-assets.mjs
node scripts/scene-server.mjs --port 4325
```

On the original workstation use `bash scripts/node.sh` in place of `node`.
Verification used Node **24.22.1**, pnpm **11.25.0** and Three **0.187.0**.
The automated suite passes **261 tests**, zero failures/skips, and covers
authoring, bindings, unit/frame transforms,
snapshot integrity/time, stale updates, round trips, missing assets/capabilities,
shared resource replacement/disposal, rapid-edit/control synchronization, server
validation and isolated generic worker execution without astronomy files.
The public author example and diff checks pass. Counts are also recorded in
[implementation status](../demo-status.md).

The optional [browser harness](../../scripts/verify-scene-browser.mjs) starts an
isolated ephemeral server, runs real browser interactions and writes ignored
`.local/f05-qa/report.json` plus screenshots. It accepts installed Playwright and
Chrome paths through `COSMIC_LEGO_PLAYWRIGHT` and `COSMIC_LEGO_CHROME`; neither is
a production dependency. The recorded run used Playwright **1.62.1**, installed
Chrome **156.0.8078.80**, headless **WebGL2/SwiftShader**, at 1440×1000 and 390×844.
Screenshots were visually inspected, including perspective/navigation,
orthographic selection/metadata, labels, narrow layout, missing-asset diagnostics,
and controlled foreground/rear occlusion. This is not a hardware-GPU performance
benchmark, cross-browser certification, full-motion review or touch-device test.

Actual checks exercise pointer picking with a stable source ID at changing
physical time; orbit/pan/zoom/reset; scientific-value equality after navigation
and marker-size edits; duplicate/remove sharing; projection/resize/fit; visible
failure diagnostics; serialized rapid edits and reload control synchronization;
and final zero owned resource counts. All ten interaction groups passed with no
browser console/page errors. In the controlled
depth fixture, the central pixel changes from gold `[214,170,91,255]` to teal
`[94,191,187,255]` when the front mesh is removed, and picking changes from
`front-block` to `rear-block`. Browser review caught and fixed a label texture/
material cache collision, with a regression test. Scaled-parent camera placement
was also compared with an equivalent unparented world pose.
