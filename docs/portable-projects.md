# Portable projects

A Cosmic Lego project is one UTF-8 JSON file. Open it with a workspace that has the required extension versions and builds. The workspace reconstructs the scene, plots and scientific results at the saved physical time. Playback and inspection work with no agent connected.

## Save, share and reopen

Start the companion from the repository root and open its printed loopback URL.

```bash
bash scripts/node.sh scripts/scene-server.mjs --workspace
```

The **Project** menu shows the local save name, unsaved changes, recipe status and saved playback time. Move the playhead to the physical time you want to preserve.

- **Save locally** writes a named slot in `.local/projects/<name>.json`. Choose 1–64 lowercase letters, digits, underscores or hyphens, starting with a letter or digit. Use a new name to keep another version. To replace an existing slot, use the current slot or select the intended entry in **Saved projects**.
- **Open selected** loads the chosen slot. **Import JSON…** loads a downloaded file as an unnamed, unsaved workspace. Save current edits you want to keep before either action. Both start a fresh load generation and a new Undo history.
- **Download JSON** exports the current accepted construction and displayed time. The two conversation checkboxes control the local save and download independently. They start unchecked on each project load. Check the download box explicitly to share public messages, even when a local save includes them.
- **Refresh list** reads current disk versions. The menu distinguishes an edited construction from a playhead that has moved since the last save.

Use `--project-dir /absolute/dedicated/directory` to change local storage. The default store holds up to 128 named projects on a local filesystem with POSIX file and directory sync support. For an optional native connection, configure `--codex` at startup. Its `--agent-workspace` is separate from the project store.

To try a saved moving-point, field and seeded-accumulator construction, run the example once with an unused `portable-fixtures` slot, then open that slot in the menu.

```bash
bash scripts/node.sh examples/portable-project.mjs --directory "$PWD/.local/projects"
```

## Inside version 1

| Manifest field | Contents |
| --- | --- |
| `format`, `version`, `savedFrom`, `graph` | `cosmic-lego.project`, version `1`, the saved historical identity and the accepted F01 construction. Stable object IDs, scientific definitions, units, frames, relationships, scene bindings and floating-panel layout live in this graph. |
| `requirements`, `assets`, `dataSources` | Direct and transitive extension pins including implementation ID, version and build. Asset records identify each definition, source and license. F05 regenerates content IDs from produced content and dependency identities. Source citations for scientific data remain readable provenance. |
| `source`, `resources` | The original recipe, any included companion files and a snapshot of its original construction. A separately labeled generated JavaScript reconstruction describes the *current* graph. Each resource has inline content, a logical relative name and a SHA-256 digest. |
| `playback` | `policy: "replay-from-initial"`, physical time with units, evaluation mode, per-node settings including applicable seeds, and selected output ports. F04 reconstructs state from the declared initial conditions. The file carries no checkpoint or live random generator. |
| `sharing`, `timeline`, `integrity` | Explicit transcript and receipt inclusion flags, a versioned timeline extension, and SHA-256 digests of the canonical graph and manifest body for content verification. |

Each scientific citation names its producer, source, and license. For example, `{"nodeId":"arrival-field","source":"Synthetic nominal scan times generated by the timing-gate recipe","license":"BSD-3-Clause"}`.

**Author recipe** compares the accepted graph with the recipe’s recorded output. An edit can change the status to *Construction has changed since the recipe ran*. Undo can restore a match. A recipe can also be unavailable. Opening only decodes its text. Rerunning a reviewed recipe is a separate authoring action with its own trusted code and dependencies.

The workspace writes compact accepted-command receipts with affected IDs, counts and historical before/after revisions. When the public transcript is excluded, the host also strips turn and call associations. Included messages carry only a public ID, turn ID, role and text. Reopening displays the archived conversation as disconnected and retires the previous session’s grants. Connecting later creates a new native session. Review authored text before sharing. The format rejects recognizable credential patterns in transcript text, while arbitrary sensitive prose still requires the author’s judgment.

## JavaScript and local HTTP

The synchronous format API snapshots an accepted project. Supply the trusted registry, binding and presentation layer for the receiving workspace.

```js
import {
  createPortableManifest, serializePortableManifest, openPortableManifest,
} from './src/portable/format.js';

const manifest = createPortableManifest({
  project, registry, binding, layer,
  playback: { time: { value: 2, unit: 's' }, mode: 'auto' },
});
const json = serializePortableManifest(manifest);
const opened = openPortableManifest(json, { registry, binding, layer });
// opened.project has a fresh generation. opened.sourceStatus describes its recipe.
```

Pass `source: { path, language, text, producedGraph, files? }` to include authored source. Capture `producedGraph` when the recipe finishes. Each companion file has `path`, `language` and `text`. Use `portableOptions(opened.manifest)` to retain these associations on a later save. The low-level format API exposes separate `includeTranscript` and `includeReceipts` options, both false by default. The companion adds an F04 replay and scene compilation check before save, export, open or import. [Runnable round-trip example](../examples/portable-project.mjs)

Local HTTP clients use the workspace origin and `application/json`. All POST requests include `expected`, the full current `{ projectId, generation, revision }` from state. Success returns `{ ok: true, result }`. On failure, inspect `error.code`, `error.message` and `context.identity`.

| Route | Request and result |
| --- | --- |
| `GET /api/projects/state` | Current identity, slot name/version, dirty state, source status, transcript inclusion and playback settings. |
| `GET /api/projects/list` | Array of `{ name, version }` disk slots. |
| `POST /api/projects/save` | `name`, `expectedVersion`, optional `time` or `playback`, optional `includeTranscript`. Returns updated status. Use `null` for a new slot or its observed disk hash for replacement. |
| `POST /api/projects/open` | `name` and the observed `expectedVersion` to open exactly the listed file. Returns new status. |
| `POST /api/projects/export` | Optional `time` or `playback`, optional `includeTranscript`. Returns the manifest. |
| `POST /api/projects/import` | `document` containing the parsed JSON object. Returns new status. |

An explicit `playback` may supply `mode` (`auto`, `analytic` or `stateful`), `time`, per-node `settings` and `targets: [{ nodeId, port }]`. The companion also evaluates every bound scene and plot source. On reopen the gateway uses the saved playback defaults. A worker diagnostic or the host’s 30-second verification deadline can prevent a file operation from completing.

## Validation and recovery

The reader checks version, hashes, resource names and inventory, installed requirements, asset provenance, graph validators, replay settings and public record schemas. Source paths resolve only to inline resources. Unsupported versions require an explicitly installed synchronous migration. Host code can register consecutive steps with `createMigrationRegistry().register(from, to, migrate)` and pass `migrations` to `openPortableManifest`. The resulting document goes through current validation.

A document is limited to 16 MiB, 500,000 data entries and 100 nesting levels. The graph limit is 2,000,000 compact JSON bytes. Up to 32 inline resources are allowed, with 256 KiB per authored file and 2 MiB total authored text. The optional timeline accepts inert version-0 metadata up to 16 KiB. Version 1
supports up to 64 KiB of authored tracks and transactions, plus configuration
hashes and transitive implementation pins checked on import. To attach or replace
a sequence, pass its `timeline` definition to the save or export route. See
the [authored timeline guide](authored-timelines.md). A file can contain up to 200 public messages totaling 512 KiB and 256 accepted-command receipts.

Local saves sync a temporary file, recheck the active identity and expected disk version, then atomically rename and sync the directory. On `STALE_TOKEN` or `STALE_TRANSCRIPT`, refresh and save the current accepted state. On `STORE_CONFLICT`, refresh the slot list and inspect the on-disk version or choose a new slot. If directory sync fails after publication (`STORE_DURABILITY`), reread the disk version before retrying. Incomplete temporary files from a dead writer are discarded. A failed validation or replay leaves the active project available for inspection and saving.
